# 关注整理所 / TidyFollows — 上线前规划

> 当前版本：v1.0.2（商店候选版）
> 本文用于后续讨论，不代表已决定上线时间。

## 1. 目标与原则

- **先把核心做稳**：找出「我关注了、对方没回关」的人，并安全地按用户选择清理。
- **本地优先**：不上传名单、不接服务器、不做统计和广告。
- **用户确认**：取关必须由用户勾选并二次确认，不自动执行。
- **低风险分发**：ZIP / 官网为主，Chrome 商店作为可选项。
- **不着急**：先完成决策和测试，再提交商店。

## 2. 当前状态

### 已实现
- 互关检测（Following + lookup；Followers 第一页使用网页端捕获响应）
- 批量取关（预览、特别关注跳过、4–8 秒随机间隔、停止/续跑）
- 特别关注、备份恢复、一键自检
- 本地存储、无远程代码、无 X API Key
- v0.2.0 已完成品牌替换（暂定名：关注整理所 / TidyFollows）

### 暂不提供
- 分享卡（入口已移除，代码保留）
- 可编辑的时间间隔（固定 1.5s / 4–8s）
- 多账号切换、推文内容清理
- 商店自动更新（当前为手动加载/替换）

### 已知问题
| 问题 | 影响 | 处理方向 |
|---|---|---|
| 粉丝名单只稳定拿到第一页 | 粉丝 >20 的账号，「我未回关」可能不完整 | 后续用「驱动页面加载 + 捕获响应」补齐，或在 UI 明确标注部分结果 |
| 自检写接口探测误报 404 | 可能让用户误以为取关不可用 | 改探测方式或降级为「无法确认」 |
| 大规模场景未验证 | 上千关注、限流、长时间任务稳定性未知 | 按测试矩阵补测 |
| 账号连接依赖页面 DOM/预热兜底 | X 改版可能失效 | 增加诊断与错误提示，必要时做接口发现 |
| X 内部接口可能变化 | 功能可能临时失效 | 保留刷新参数、自检、更新文档 |
| 商店审核风险 | 自动化操作可能违反 X ToS | ZIP 优先；商店描述克制；准备审核说明 |
| 无英文界面 | 海外用户门槛 | 决定是否做 i18n |

## 6. 风险与应对

| 风险 | 概率 | 应对 |
|---|---|---|
| Chrome 商店以「自动化/违反 X ToS」拒绝 | 中 | ZIP 优先；描述克制；审核备注说明用户确认与本地处理 |
| X 接口变更导致功能失效 | 高（长期） | 自检、刷新参数、响应捕获架构、快速更新 |
| 大规模取关触发账号限制 | 中 | 固定 4–8 秒间隔；单次数量提示；可停止 |
| 粉丝分页不完整 | 中 | 明确标注「部分结果」；后续驱动页面捕获 |
| 商标/名称冲突 | 未知 | 上线前查 CNIPA/USPTO/域名/商店同名 |
| 用户数据丢失（清理浏览器/卸载） | 中 | 备份提醒、导出/导入、清空前确认 |
